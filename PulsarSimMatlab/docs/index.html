Pulsar navigation: synthetic data and processing pipeline

A MATLAB pipeline that simulates a pulsar signal through the interstellar medium and a realistic radio receiver, then processes the receiver data back into times of arrival (TOAs) with honest uncertainties. Every processing stage is checked against the simulation's ground truth.

Folder: PulsarSimMatlab/ · Docs checked against commit 9b959f0 (8 Oct 2026) · Detailed reference: logs/current_project_notes.md

The idea in one paragraph

A pulsar is a rotating neutron star that sweeps a radio beam past us once per turn, with a period that is stable to better than a microsecond over years. If you know where you are, you can predict when each pulse arrives. Turned around: if a pulse arrives earlier than predicted, you are closer to the pulsar along the line of sight, by the speed of light times the difference (1 µs ≈ 300 m). Arrival times from at least four pulsars in different directions give a 3-D position plus a clock offset, like GNSS but with natural beacons. This project builds the part that turns raw antenna voltages into those arrival times.

What makes this hard

  • The pulse is noise. Pulsar radio emission is broadband Gaussian noise whose power rises once per turn. There is no waveform to correlate with; the information is in the variance. See Physics: emission.
  • It is extremely weak. For the target hardware (a 0.61 m² array) the pulse peak is about −54 dB below the receiver noise. One pulse is invisible; a TOA needs hours of folding. See Reference scenario.
  • The sky smears it. Free electrons delay low frequencies more than high ones (dispersion), smearing each pulse over milliseconds across the band. It must be undone exactly. See Physics: dispersion.
  • Man-made interference is far stronger. One radar pulse can carry the energy of ~80,000 pulsar pulses at −54 dB, so interference must be removed (blanked), not just reduced. See RFI excision.
  • Error bars must be honest. A navigation filter trusts the stated σ of each TOA. A small TOA with a wrong σ is worse than a large one with the right σ. Much of the code exists to make σ exact. See TOA estimation.

Quick start

  1. Open MATLAB in the PulsarSimMatlab folder (paths in pipelineParams.m are relative).
  2. Edit parameters in pipelineParams.m (pulsar, receiver, SNR, RFI, processing, front end); see parameters.
  3. In main.m, choose which stages to run (runStage.*) and which check plots to show (plots.*). The sky stage is slow and independent of the noise; set it to false once its files exist.
  4. Run main. It prints the disk estimate, each stage's progress, the TOAs, the detection result and the validation against the truth.

Disk use is large: about 61 GB per second of simulated data at 800 MHz (three 4 GHz real files dominate). The default L = 0.1 s needs about 6 GB. See Run scripts.
