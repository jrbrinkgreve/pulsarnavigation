PulsarSimMatlab · documentation

Navigating by pulsars

A MATLAB pipeline that simulates a pulsar's radio signal on its way through interstellar space and into a small radio receiver. It then turns the raw receiver voltages back into pulse arrival times (TOAs), with honest error bars. Every processing step is checked against the simulation's ground truth.

Start with the physics → See the pipeline Parameters

The idea. A pulsar sweeps a radio beam past us once per turn. Its period is stable to better than a microsecond over years. So if you know where you are, you can predict when each pulse arrives.

Turn this around. A pulse that arrives early means you are closer to the pulsar along its direction: by the speed of light times the time difference. Arrival times from four or more pulsars in different directions give a 3-D position plus a clock offset. It works like GNSS, with natural beacons.

This project builds the part that turns raw antenna voltages into those arrival times.

What makes this hard

The pulse is noiseNo waveform to correlate with: the information is in the power, so the processing squares, then folds. It is extremely weak~54 dB below the noise on the target hardware. One pulse is invisible; a TOA takes hours. The sky smears itInterstellar electrons spread each pulse over 31.5 ms across the band (DM 25). It must be undone exactly. Interference is far strongerOne radar pulse outweighs ~80,000 pulsar pulses: it must be blanked, not reduced. Error bars must be honestA navigation filter trusts the stated σ. Much of the code exists to make it exact.

Now: block D, motion and the clock. The receiver moves with the Earth and its ship, and it times its data with its own oscillator. Block D predicts the pulse phase the receiver should see, so that a fold stays aligned over hours. It also gives the simulator a true trajectory and clock, against which the observer's assumed ones are wrong. The difference is the navigation signal. The phase-prediction and navigation pages have the functions, and the localisation page the frames, time scales and relativistic corrections behind them.

Before that: block C, the fast simulator. A TOA takes hours of data, far more than a simulation of every voltage sample can handle. The fast simulator therefore draws the folded profiles straight from their known statistics: hours of data take seconds. It is validated in Jasper's runs, and its scenario runs give TOA budgets for B0329+54, seen from the Netherlands, and for J0437, seen from 30° S.

Next: the simulator's truth in the scenario runs, then the navigation fit: first B0329+54's 2-D site offset (D4). After that: several pulsars and the navigation solution (E). Details and reasons: roadmap.

Quick start

  1. Open MATLAB in the PulsarSimMatlab folder. The paths in pipelineParams.m are relative to it.
  2. Set the parameters in pipelineParams.m (see parameters).
  3. In main.m, choose the stages to run (runStage.*) and the check plots (plots.*). The sky stage is slow, and it does not depend on the noise. Set it to false once its files exist.
  4. Run main. It prints a disk estimate, each stage's progress, the TOAs, the detection result and the validation against the truth.

Disk use is large. With the default settings (channel path with excision) a run writes about 72 GB per second of simulated data; the full-band path writes about 61 GB. The default L = 0.2 s therefore needs about 14 GB. See run scripts.
