Stages 5–6 · Full-band front end

The original processing path: one coherent dedispersion filter over the whole 400 MHz band, then square-law detection into 1 µs bins. It is simple, exact, and the validated reference that the channelized path is compared against.

Selected with frontEnd = 'fullband' in pipelineParams.m. Default since 8 Oct 2026 is 'channels' (channelized front end).

5 · applyInverseDispersion validated

info = applyInverseDispersion(inFile, outFile, fs, fLO, DM, fLow, fHigh, 'RefFreq', refFreq)

Full interface and help text of applyInverseDispersion →

Purpose

Remove interstellar dispersion from complex baseband data, exactly: the inverse of applyDispersionStream, using only the catalogue DM and the receiver settings.

Physics

For every FFT bin with RF frequency f = fLO + fbb inside the band:

Hinv(f) = W(f) · exp(−i2π·K·DM·(f − fref)² / (f·fref²)),   0 outside the band

Its group delay is −(τ(f) − τ(fref)): lower frequencies are advanced by up to 6.3 ms, so the filter is non-causal (it needs future samples). Because it acts on voltages, it removes dispersion exactly at every frequency.

Why the same W and fref as the forward stage

An exact round trip needs the same constant, DM, reference frequency and sign. A different RefFreq would leave a constant shift τ(fref,fwd) − τ(fref): harmless for relative timing, but a TOA definition. The taper W (8 MHz raised-cosine edges) keeps the filter's impulse response short, so the guard and the leakage check work.

Algorithm

  • Checks: band strictly inside fLO ± fs/2; fref in the band (unless AllowRefOutsideBand).
  • Overlap: nFuture = ⌈(τ(fLow) − τ(fref))·fs⌉ + g and nPast = ⌈(τ(fref) − τ(fHigh))·fs⌉ + g, guard g = 2.5 µs·fs. Reference run at 500 MHz: 3,152,472 and 1250 samples.
  • Filter on the FFT grid: written directly for the in-band signed bins (in chunks, phase in double). Complex data, so no Hermitian symmetry.
  • Leakage check: one inverse FFT of H; the energy outside lags [−nFuture, +nPast] must be tiny (reference run 0; warning above 10⁻⁶). This proves the overlap is long enough.
  • FFT size: candidates from 2nextpow2(2·overlap) up to the whole file, cost nblocks·Nfft·log₂Nfft, 56 bytes per sample, within MaxMemoryGB (4). Reference run: 2²⁶, 95 % useful, 8 blocks, 3.76 GB, 7.4 s for 1 s of data.
  • Overlap-save with one preallocated buffer [past | outputs | future], shifted each block; zeros before the start and after the end of the file.
  • fullySupported = [nPast + 1, N − nFuture]: the outputs that saw their complete sweep. The last ~6.3 ms did not (the forward stage dropped that energy past the file end); the fold uses only fully supported data.
Why overlap-save here and overlap-add in the forward stage

Both are exact. Overlap-save suits a non-causal filter with very asymmetric reach (6.3 ms future, a few µs past): one buffer holds past, output and future, and each block keeps only the outputs that saw a complete window.

AllowRefOutsideBand (6 Oct 2026)

Added for the channelized front end. Default false: fref must lie in [fLow, fHigh]. True: any fref > 0, so every 3.125 MHz channel can be referenced to the top of the whole band. The filter formula is exact for any fref (its phase splits into the 1/f dispersion term, a linear term = pure delay, and a constant); a reference above the band only adds a pure advance, so all the overlap moves to the future side. nFuture/nPast use max(⌈…⌉, 0) + g, unchanged inside the band. Regression: the full-band path reproduces test_IQ_dedispersed.dat bit for bit.

Options and outputs

Options
RefFreq (fHigh), AllowRefOutsideBand (false), EdgeFrac (0.02), GuardTime, Nfft, MaxMemoryGB (4), CheckLeakage (true), MaxLeakage (1e-6), SaveInfo, Verbose

Not checked internally

The stage trusts its inputs: the DM (a wrong DM leaves a residual sweep), the reference-frequency convention vs the TOA definition, the receiver's frequency mapping (no spectral inversion assumed) and the true sample rate (passed through the info chain). See limitations.

6 · detectPower validated

info = detectPower(inFile, outFile, fs, fLO, f_out, 'FullySupported', info_dedisp.fullySupported)

Full interface and help text of detectPower →

Purpose

Square-law detection: |z|² averaged over time bins of 1/fout (1 µs). This is where the data rate collapses (800 M complex samples/s → 1 M power values/s), so everything downstream is cheap.

Physics

After dedispersion the pulse is still noise; only its variance carries the signal. |z|² = I² + Q² estimates the variance, and a profile-weighted sum of |z|² is the optimal (Neyman–Pearson) statistic for variance-modulated Gaussian noise. So square-law detection, then folding, then matched filtering is the optimal order. Per 1 µs bin the noise is 1/√(Bn·Δt) ≈ 1/√390 ≈ 5.1 % of the mean.

Algorithm

  • binLen = round(fs/fout) samples per bin (500 at 500 MHz, 800 at 800 MHz).
  • Fast path (one channel, no band): I² + Q² straight from the raw read, no complex arrays, no square root, sums in double.
  • Channelized path (NChan > 1 with Band): rectangular non-overlapping FFT frames whose length divides binLen (≥ 8 FFT bins per channel), |Z|² summed into channels by one matrix (Parseval normalization), so channels of a full-baseband band sum exactly to the total. Up to ~32 clean channels at 1 µs bins. (The 128-channel front end uses channelizeIQ instead.)
  • Timing: bin k (1-based) is stamped at the centroid of its samples, tk = T0 + ((k−1)·binLen + (binLen−1)/2)/fs = binTime0 + (k−1)·binDt. The boxcar is symmetric, so it does not bias arrival times. A trailing partial bin is dropped.
  • fullySupportedBins: the bins whose samples are all fully supported.
Why the bin is stamped at its centroid, not its start

Stamping at the start would label every bin half a bin before its content, so every TOA would come out half a bin (0.5 µs) early. The centroid of a symmetric boxcar is the unbiased time; with linear phase assignment in the fold (fold) it carries through to the TOA.

Validation

  • Noise-free, L = 1 s: normalized residual of 127,512 on-pulse bins mean −0.0016, std 1.0015 (expected 0 ± 0.0028, 1 ± 0.0020); per-pulse centroid offsets rms 0.301 µs vs 0.277 µs expected.
  • −5 dB: noise baseline 1.232 vs 1.233 predicted; off-pulse normalized residual std 0.9995.
  • Run time 1.2 s per second of data (I/O bound).
