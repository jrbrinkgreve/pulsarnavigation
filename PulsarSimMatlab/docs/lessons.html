Bugs and lessons

Bugs found and fixed so far, and what each one taught. Many conventions on Conventions and why exist because of one of these.

In short

Most bugs were timing or bookkeeping errors that a quick check could not see: a sign shared by the forward and inverse filter, an unremoved filter delay, a missing covariance. Each one became a rule. Check each direction against the physics; remove every delay; track every correlation; test every branch, the way Jasper runs it. The statistical lessons are about checks themselves: quote their uncertainty, and do not trust one seed.

Findings that changed the design

Not bugs, but results that changed a plan:

  • Narrow-channel noise (6 Oct). The radiometer model assumes independent time bins; in 3.125 MHz channels bins are correlated. → exact V, X(L) through the fold (powerCovariance, 'NoiseCoeffs').
  • No simple variance rule after blanking (experiment 3a). Errors up to ±45 % for W² and W models. → exact per-bin weights (blankingWeights).
  • W = 0 bins still had power (found with blankingWeights). Filter-tail leftovers biased nearly empty phase bins by up to +285 %. → the fold drops their power.
  • White-input assumption for blanking (blankingWeights). Channel samples are not white; ~1 % error in W for nearly empty bins. → the mean uses the true channel spectrum.
  • Exclusion rule lost data (found with blankingWeights). Whole channels dropped from sub-ints with any empty phase bin. → optimal weighting.
  • Gamma threshold tail too thin (detectRFI). 1.1× the intended false flags at 10⁻⁶. → exact phase-type thresholds.
  • Long detection windows blanked the bright pulse (detectRFI). 14 % of on-pulse data at −5 dB with 256-sample windows. → windows ≤ 16 samples.
  • Radar sidelobes survive per-sample excision (the locked radar). A locked radar left a 150 µs bias at −54 dB. → the frequency guard, ±7 channels.
  • Rotating-radar sidelobe pulses are missed one by one. → the periodic mask (periodicRFI), which blanks the predicted pulses.
  • A χ² threshold of 2 is blind on 34,000 bins (16 Oct). On the channel path it is ~130σ away, so error bars a few percent too small pass silently. → pChi2, reported alongside the drop rule (TOA).
  • The band-edge channels hold almost no pulse (19 Oct). pChi2 was not uniform on the channel path at −5 dB: the fit assumes equal gain, but the simulated band-edge taper leaves channels 1 and 128 with 2 % of the pulse. The excess grows as SNR², and is gone at −15 dB. → kept as a known simulator artifact (roadmap item 3), parked with the per-channel calibration.
  • Coarse bins cost more at low SNR (20 Oct). With B0329+54's five components at NBin 1024, the error bars were 18 % too small at SNR 7, although the bins were inside the 1/5 rule. And the half-maximum width missed the narrow components. → NBin 2048, and the warning at 1/10 of the spectral template width (TOA).
  • Catalogue widths understate real profiles (20–21 Oct). B0329+54's five components put the same flux over twice the area: a 3 dB lower peak and ~3× the data per TOA. J0437's wings cost ~5×. → multi-component templates and profiles (scenario).
  • Seven lags are not enough for narrow carriers (21 Oct). A 200 kHz carrier's power correlation has a sidelobe at lags 7–20. → rfiProfile 'Lmax'; the RFI profiles use 30 lags.
  • White-noise thresholds false-flag continuous narrow carriers (21 Oct). About 1400 false windows per second in each carrier channel made the blanking data-dependent: phase bins with blanking came out 4–9 % noisier than modelled. → per-channel thresholds from each channel's own correlation (excision).
  • A narrow core on a broad component gives rare outliers (20–21 Oct). About 0.3–0.5 % of B0329+54's TOAs at SNR ~7 land one core width off, and χ² cannot flag them; over 100 days 1.9 % lie beyond 3σ. → handled in the navigation fit and filter, not by longer groups: their error model is a mixture with 2 % of the TOAs 4× wider (navigation).
  • The port clock is never exact (22 Oct). Taken as exact in the ship's calibrated start, it made the clock's error bars 2.6× too small; the position barely suffered, because the clock's wander absorbs the offset within a day. → navFilter 'ClockPrior'.
  • A prior shrinks a strong current (22 Oct). One simulated ship drew a current of 0.76 m/s, 2.5σ of the filter's 0.3 m/s prior. Even with ideal data the filter pulls it towards zero. That is a property of the estimate, not a bug.

Statistical lessons

  • Shared realizations make "independent" checks correlated. The phase D ratios (1.03–1.06) and the phase E T0 std (1.10) looked like a 5–10 % hole in the noise model; they came from the same 10 noise realizations. A long independent H0 run settled it (T0 std 1.008).
  • One seed can mislead. The +3.7 µs centroid offset was a 1.8σ fluctuation of seed 43, repeated by every run that used the same noise.
  • Quote the uncertainty of a check. With 8 TOAs a ratio of 0.84 is consistent with 1 (±25 %); with 90 TOAs ±0.075.
  • Common random numbers tie the points of a sweep together. In the channel path's weak-regime sweep, rms/pred was 1.07–1.08 at every point. That is one shared fluctuation of the same 10 noise seeds, not an effect of SNR.
  • A surprising number from one run can be scatter. J0437's pull width of 0.88 in one scenario run looked like error bars too large; a second run gave 0.94, and adaptive and fixed groups on the same data both gave ~1.1. Likewise B0329+54's first 30-day site fit came out 2.2σ low; a 1000 km run with the same seeds was low by the same amount, and new days landed on the truth.
  • Errors correlated along a track make one run noisier than its pulls suggest. A smoothed ship track's errors are correlated over days, so the pulls of one ship's TOAs are not independent, and two-sigma effects in single runs looked like bugs. → pulls at fixed times over many seeds, against an ideal twin on the same TOAs (validation). The same pooling error was first in testNavFilter's criteria.
