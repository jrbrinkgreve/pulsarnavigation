Stages 1–2 · Sky: pulsar signal and dispersion

The simulated sky: a noise-like pulsar signal, then the interstellar medium's frequency-dependent delay. Both run at a real 4 GHz sample rate and know the full ground truth.

Run by runStage.sky in main.m · slowest part of the pipeline · independent of receiver noise, so it is run once and reused.

1 · generatePulsarSignal validated

info = generatePulsarSignal(outFile, T, f_in, A, L, dutycycle, ...)

Full interface and help text of generatePulsarSignal →

Purpose

Write a real float32 file of a synthetic pulsar voltage, with the true pulse centre times as ground truth.

Physics

Pulsar emission is the incoherent sum of many emitters, so the voltage is Gaussian noise; the pulsar shows up as a periodic change of its variance (see physics):

x(t) = A·√G(t)·n(t),   n white, unit variance,   E[x²] = A²·G(t)

G is a periodic train of unit-peak Gaussians: the power profile. A is the noise standard deviation at the pulse peak and sets the signal scale. The noise is white from 0 to fin/2; that is a property of the simulation grid, not of real pulsars (whose spectra fall as a power law, see limitations).

Algorithm

  1. FWHM = dutycycle/100 · T (5 % of 10 ms = 0.5 ms); σ = FWHM / (2√(2 ln 2)) = 212.3 µs.
  2. Pulse centres at (k + ½)·T: the first pulse peaks at T/2 and the file starts near zero signal. These times are stored in info.pulseCenters: the ground truth for every TOA check.
  3. For each sample, find the nearest pulse k0 = round(t/T − ½) and sum the Gaussians of nNeighbors = ⌊11.75σ/T + ½⌋ pulses on each side (every Gaussian that reaches 10⁻³⁰ of the peak; at 5 % duty none, only the nearest pulse; 13 Oct 2026, bit-identical to the earlier max(1, ⌈6σ/T + ½⌉)), then divide by the exact peak value of that periodic sum (peakNorm), so overlapping pulses keep their true shape and the peak is exactly 1. Above 20 % duty it warns (generatePulsarSignal:overlap): real pulsars stay below ~20 % (lowered from 50 % on 13 Oct 2026).
  4. N = round(L·fin) + 1 samples (inclusive of t = L, which is why file lengths end in …001), in blocks of 4·10⁶ samples. Times in double; only the written samples are single.
Why 'power' envelope mode (default)

The processing detects power, so the parameter that matters is the FWHM of the power profile. In 'power' mode the amplitude envelope is √G and the power profile G has exactly the stated FWHM. The older 'amplitude' mode (amplitude G) makes the power profile √2 narrower, which the template would then have to account for.

Why first pulse at T/2

With ephem.TRef = T/2 and Φ0 = 0, every true pulse peak is at an integer rotational phase. The fold then cuts turns half-way between pulses, and the expected TOA phase offset is zero.

Options and outputs

Options
Seed (private mt19937ar stream; clock-derived and reported if omitted), EnvelopeMode ('power' / 'amplitude'), BlockSize (4e6), SaveInfo, Verbose (progress about every 10 %)

2 · applyDispersionStream validated

info = applyDispersionStream(inFile, outFile, DM, fs, fLow, fHigh, ...)

Full interface and help text of applyDispersionStream →

Purpose

Apply interstellar dispersion to the RF file, exactly, inside the observed band, streamed through a long FIR filter.

Physics

A cold plasma gives a phase advance and a group delay τ(f) = K·DM/f². Only the delay relative to a reference frequency is applied: RefFreq = fHigh = 1.6 GHz by default, so the top of the band keeps its time and lower frequencies arrive later (up to 6.302 ms at 1.2 GHz for DM 5). The bulk delay τ(fref) = 8.103 ms is recorded in info.bulkDelayRef but not applied.

The transfer function

H(f) = W(f) · exp(+i2π·K·DM·(f − fref)² / (f·fref²)) · exp(−i2π·f·s0/fs)

Its group delay −(1/2π)·dφ/df = KDM/f² − KDM/fref² + s0/fs: the dispersion delay relative to fref, plus s0 samples that put the kernel's zero lag inside the kernel (and are removed again when writing). W(f) is 1 in the band, has raised-cosine (sin²) edges of width EdgeFrac·B = 8 MHz inside the band, and is 0 outside.

Why the filter is band-limited, and why that is still exact
  1. Delays diverge as f → 0; no finite kernel can represent dispersion over all frequencies.
  2. Dispersion is phase-only (|H| = 1) and frequency-preserving: energy never moves between frequencies, so content outside the band cannot affect data inside it.
  3. Dispersion and the receiver bandpass are both linear time-invariant filters, so they commute. Band-limiting before or after dispersion gives identical in-band data.

So W models the receiver bandpass, not the sky. (Caveat: a real receiver is not ideal; strong out-of-band RFI can create in-band products through non-linearity. Not modelled.)

Why raised-cosine edges, not a time window

An earlier version applied a Hann window to the chirp in time. In a chirp, time maps to frequency, so the window attenuated the low end of the band. Tapering in frequency with sin² edges avoids that, and the smooth edge keeps the kernel's time response short (the ringing fits in a guard of 20 / edge width = 2.5 µs). See bugs and lessons #3.

Kernel design (makeDispersionKernel)

  • Guard g = ⌈GuardTime·fs⌉ = 10,000 samples (2.5 µs at 4 GHz) on each side of the sweep.
  • Zero-lag index of fref: s0 = g + ⌈(τ(fref) − τ(fHigh))·fs⌉ (= 10,000 for fref = fHigh).
  • Kernel length Nk = s0 + ⌈(τ(fLow) − τ(fref))·fs⌉ + g + 1 = 25,229,772 taps at 4 GHz, DM 5.
  • Designed on a frequency grid of 2nextpow2(2Nk) = 2²⁶ points, in-band bins only, phase in double (the chirp spans about 1.08 million turns of phase). The linear shift term uses mod(k·s0, Nf), exact. Hermitian spectrum → real kernel, truncated to Nk. info.kernelLeakage = energy lost by truncation (3.5·10⁻¹³).
  • Kernel energy Σh² ≈ 0.195 = the fraction of white-noise power passed ≈ 2(B − 1.25·edge)/fs.

Streaming (overlap-add)

Each block of n samples is convolved with an FFT of size ≥ n + M − 1; the last M − 1 output samples (the carry) are added to the next block. chooseBlockSize requires block length ≥ M − 1, so a carry only ever spills into the next block, and picks the power-of-two FFT with the lowest total cost nblocks·Nfft·log₂Nfft within MaxMemoryGB (estimate 44 bytes per FFT sample). Output index = full-convolution index − s0, so fref stays on its original time. The output has the same length as the input; energy delayed past the end of the file is dropped.

Reference run (L = 1 s): FFT 2²⁸, block 243,205,685 samples (91 % useful), 17 blocks, ~11.8 GB, 81.5 s.

Validation

  • NumPy port: group delays exact to 10⁻⁴ µs, leakage ~10⁻¹², overlap-add equals direct convolution (~10⁻⁷).
  • Forward → IQ → inverse round trip ~2·10⁻⁶.
  • plotDispersionCheck: raw vs dispersed dynamic spectra follow the expected sweep; band-integrated power as expected.

History: why the current form

The first dispersion kernel had the wrong sign (low frequencies arrived earlier) and wrapped around inside the kernel. It went unnoticed because the old inverse conjugated the same kernel, so the round trip still worked. The current standard chirp was written from the physics, with the sign checked by group delay. An fftshift offset (a bulk delay of 8.4 ms that depended on kernel length) and out-of-band content wrapping in time were fixed at the same time. See bugs and lessons #1–4.

Limits

Memory at high DM

The kernel grows with the sweep (∝ DM). At DM 60 the forward dispersion would need about 47 GB, at DM 100 about 94 GB: more than the 24 GB machine. The processing side is solved by the channelized front end; the generator side is still open (memory-efficient FFT, dispersion at complex baseband, or per-channel generation). See roadmap.
