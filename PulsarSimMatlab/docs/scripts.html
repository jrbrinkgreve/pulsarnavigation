Run scripts

The scripts in the PulsarSimMatlab folder. main.m runs one realization; the run*.m scripts are experiments that run the same stages many times and compare with the truth. All read their parameters from pipelineParams.m and must be run with MATLAB's current folder = PulsarSimMatlab.

In short

main.m runs the pipeline once and compares its TOAs with the truth. One run cannot show whether the error bars are honest (8–9 TOAs say little), so the experiments repeat the same stages many times, each time changing one thing on purpose: the noise, the pulsar, the signal strength or the interference. Each experiment answers one question.

Which front end the experiments use

Since 19 Oct runMonteCarlo, runSNRSweep and runH0 run the front end frontEnd chooses: they simulate the receiver themselves and call processIQ, then foldToTOA or detectPulsar, as main.m does (before: full band only, with a …:fullBandOnly warning). With RFI on and the full band they warn (…:noExcision): the full band has no excision. runRFITest (also on processIQ) and runLockedRadar (its own superposition method) run the channel path. The default channel path is validated end to end over seeds by runMonteCarlo (A3b, 19 Oct), besides its unit tests.

Design choice: each experiment writes its own files

Alternative: write into data/, like main.m.

Why not: a later main.m run with skipped stages reloads files from data/. If an experiment overwrote them with another noise realization, main would pick it up (checkConsistency notices another noise seed only since 13 Oct). Separate folders keep main's files untouched.

Never run two of these at once

Scripts and tests that share files (e.g. data/chan/; the unit tests: data/test/chan/) corrupt each other's data when run in parallel: an overlapping run once gave noise 72× the radiometer value (bugs and lessons #11). main.m next to a test session is safe since 13 Oct: the tests read only data/test/.

main.m

Run control at the top (runStage.*, plots.*, closeFigures), then:

  1. paths and pipelineParams;, a disk estimate;
  2. sky (generator + dispersion) or reload; optional plotDispersionCheck;
  3. receiver (noise/RFI + IQ) or reload; checkConsistency; on the channel path with excision, a warning (main:brightExcision, since 14 Oct) when the pulsar is brighter than −5 dB or noise-free, because detectRFI then blanks the pulse itself (excision limits);
  4. processing up to the fold, one call since 19 Oct: processIQ(info_IQ, rx, ephem, proc, files, 'Reuse', ~runStage.process) (the structs from pipelineParams) runs full band (dedispersion + detection) or channels (channelizer → [detectRFI → blankChannels] → dedisperseChannels → detectChannels → [blankingWeights]) and the fold (with NoiseCoeffs or DataWeights on the channel path), or reloads them + checkProcessing, checkFold;
  5. foldToTOA (runStage.toa): TOAs, detection, good TOAs;
  6. evaluation against the truth: optional IQ, detection and fold checks (full band), validateTOA (all and good), the exact optimum (full band).

Printed reference for seed 43, −5 dB, L = 0.1 s: full band 9 TOAs, median σ 2.880 µs, SNR 93.4; channel path 8 TOAs, 2.943 µs, SNR 92.3 (with excision 2.956 µs, 91.9).

Design choice: the stages can be skipped

Alternative: always run the whole chain.

Why not: the sky stage is by far the slowest (random numbers and a 25-million-tap filter at 4 GHz) and does not depend on the noise. Changing the SNR, RFI or processing only needs the later stages. Each skipped stage reloads its info, and checkConsistency, checkProcessing and checkFold warn when files on disk were made with other parameters or from older inputs.

runMonteCarlo.m validated

The pulsar signal is fixed (sky files from main.m); only the receiver noise changes: seeds seed + (1:nSeeds), default 10. The spread of TOAs between realizations is exactly what the error bars claim to describe, so the pooled z = (TOA − truth)/σ must be N(0,1).

  • Built-in check: seed 1 = main's noiseSeed, so its TOAs must equal main's with the same frontEnd.
  • Errors if the sky files do not match the parameters (checkSkyFiles: T, f_in, L, A, dutycycle, envelope mode, seed, DM, band, refFreq; before 13 Oct only T, L, f_in, seed, DM, band).
  • Since 19 Oct: per seed the receiver simulation, then processIQ and foldToTOA as in main.m ('Verbose', false; own files in data/mc/), on the front end pipelineParams chooses (default: channels, excision, optimal weighting). Before: full band only.
  • Pooled: validateTOA on all TOAs and on the good ones; pChi2 (mean, fraction below 0.05, Kolmogorov–Smirnov distance to uniform); detection rate (unknown phase); on the channel path the blanked fraction (false flags on pure noise).

Result (−5 dB, 90 TOAs): rms/pred 0.950 ± 0.075, χ²red 0.91, 72 % within 1σ (full band; reproduced exactly on processIQ, 19 Oct; pChi2 uniform).

Channel path (A3b, 19 Oct; default: excision, optimal weighting), 50 seeds, −5 dB: 400 TOAs, all good and detected; mean error −0.03 ± 0.15 µs; rms/pred 0.956 ± 0.034; χ²red 0.915; 67.0 % within 1σ, 96.8 % within 2σ; blanked 0.0126 % of the samples. The default path's error bars are honest end to end over seeds. pChi2 is not uniform there at −5 dB (mean 0.29): the band-edge channels 1 and 128 hold almost no pulse in the simulation but the fit assumes equal gain (open item 3); the excess grows with SNR², and at −15 dB pChi2 is uniform (Kolmogorov–Smirnov 0.090; ratio 0.971).

Its blind spot

The pulsar realization is the same in every run, so its self-noise is identical everywhere and missing from the scatter. Fine at −5 dB (~4 % of the variance), wrong at high SNR. That is why runSNRSweep varies the pulsar too.

Phases D and E: TOA precision, error-bar honesty, outliers and detection versus SNR, against the exact optimum.

  • Top: nReal (10), snrList ([−25 −20 −15 −10 −5 0 10 20] dB), replotOnly (redraw from data/mc/snrSweep.mat, the last run's results).

The same sky and noise seed for every SNR (noise only rescaled: common random numbers, smoother curves; TOAs within one SNR point stay independent).

  • A true H0 pass per realization: zero sky (generator with A = 0) + receiver noise, only detectPulsar.
  • Since 19 Oct on processIQ / foldToTOA, either front end. Channel path: excision is off for SNR points above excisionMaxSNR (−5 dB; detectRFI would flag a bright pulse itself), and there is no optimum yet (item 8), so the detection theory and the SNR axes use the measured mean T0 (the matched-filter SNR at the known phase) instead. At high SNR the mean T0 is much larger than estimateTOA's SNR (T0 is normalized by the noise without a pulsar, so the pulsar's own noise is not in it; +10 dB: 2332 vs 493), which only matters where PD = 1 anyway.
  • Figure: σTOA vs SNR (rms, robust, predicted, optimum), ratios, |z| < 1 and outliers, detection.
Design choice: H0 is a zero sky (Jasper, 5 Oct)

Alternative: use a very low SNR, such as −50 dB, as "no pulsar".

Why not: −50 dB is not "no pulsar". It is a real small-antenna operating point that only needs long integrations. H0 must be a sky with no pulsar at all.

Design choice: the same random numbers at every SNR

Alternative: new pulsar and noise realizations at every SNR point.

Why not: with the same sky and noise seed at every SNR (only the noise level is rescaled), the curves against SNR are smooth: the differences between points come from the SNR, not from new random numbers. The TOAs within one SNR point stay independent, so the statistics at each point are unaffected.

Results: validation record. Variant run on 6 Oct with nReal 20 and −20…−15 dB in 1 dB steps: the threshold sweep. Its results are in data/mc/snrSweep.mat (the last run); the phase D/E sweep above (−25…+20 dB, 10 realizations) was kept as data/mc/snrSweep_phaseDE.mat before it.

runH0.m validated

Many independent noise-only profiles to test the H0 side of detectPulsar and the noise covariance model behind it (and behind the TOA error bars).

  • nPass (100) passes, zero sky made once, receiver noise with seed seed + 10000 + i (no overlap with the sweeps), the same processing as main (since 19 Oct processIQ, then detectPulsar, on the front end pipelineParams chooses; before: full band only); 9 complete turns per pass on the full band (~8 s), 8 on the channel path (~40–55 s).
  • Collects T0, Tmax, noiseRatio, the circular autocorrelation of each normProfile, and the model correlation from weightX: full band lag 1; channel path lags 1–3 of the combination detectPulsar uses (optimal: weights 1/variance per channel; equal noise levels assumed). With excision also the blanked fraction per pass: on pure noise, the false-flag rate of detectRFI.
  • Exceedances at PFA 10⁻¹, 10⁻², 10⁻³; saves data/mc/h0Run.mat; figure.

Motivation: the phase E sweep gave T0 std 1.10 ± 0.075 under H0 and error-bar ratios of 1.03–1.06, all from the same 10 noise realizations: possibly a 5–10 % hole in the noise model. Outcome: T0 std 1.008 ± 0.024, lag-1 correlation 0.2484 vs 0.2501 modelled, nothing beyond lag 1. The noise model is complete; the earlier hint was a fluctuation of the shared realizations.

Channel path (19 Oct; excision, optimal weighting), 100 passes, 800 profiles: T0 mean +0.033 ± 0.035, std 1.023 ± 0.025; false alarms at PFA 0.1 / 0.01 / 0.001: 87 / 10 / 2 at the known phase (expected 80 / 8 / 0.8), 66 / 6 / 1 at the unknown phase; lag-1 correlation 0.2567 vs 0.2580 modelled, lags 2–3 ≈ 0; blanked fraction on pure noise 0.0049 % (detectRFI's false flags). The default path's detection statistics are calibrated end to end.

runRFITest.m (B4) validated

For each case (noise only; each source of rfiScenario alone; all five) the receiver stage runs with that RFI and main's noise seed (so the noise is the same in every case), then the channel path twice: without and with excision, both with optimal weighting. A table: blanked fraction, good TOAs, median SNR, median TOA error, rms/pred, median χ², total offset. Since 19 Oct both passes are processIQ (with excision false / true; the filterbank runs in each) + foldToTOA. Requires frontEnd = 'channels'; stops if main's sky files do not match the parameters (checkSkyFiles, 13 Oct).

Results: RFI excision.

Rotating radar cases (B5c-2, 8 Oct): cases 8–11 use the scenario radar on a rotating antenna (10 s scan, 39 ms beam): one beam passage centred in the file (−30 dB floor), and sidelobes only (beam 5 s away) at −25 / −30 / −35 dB. For pulsed sources the table adds, from the source's parameters (ground truth, validation only), the fraction of its pulses blanked in its own channels and the fraction of its energy in missed pulses. runCases picks a subset of the cases.

LTE cases (B5d-2, 8 Oct): cases 12–13: the 'noise' type, 20 MHz at 1472 MHz (inside LTE band 32), INR −10 and 0 dB. Results: receiver and excision limits.

Realistic scenario (B5e, 9 Oct): case 14 = rfiRealistic (~3 min); case 15 = the same with Inmarsat as ten narrow (200 kHz) carriers inside channels 105–114 instead of three wide blocks (~5 min), the worst case for the TOA error bars. A case can be given as {sources, label}. Since 9 Oct the excision path also runs periodicRFI when periodicMask is true, as main.m does (before: detectRFI only).

Per-channel noise check (B5e, every case; evaluation only): r = var/mean² of the off-pulse fold bins (more than 3 FWHM from the pulse) in a channel, over the median channel's (1 = behaves like the model). Two table columns: the number of channels with r > 1.1, and how much the TOA error bars are too small because of them, √(ΣF r/ΣF) − 1 with F = 1/ac² (the fit's channel weights). After the table, per run with excision: the channels with r > 1.1 or with flagged windows > 10× the expected false flags and > 3× the median channel's, with the sources covering them (ground truth, for labels only), and the periodic emitters found. Valid only when little is blanked (r compares with the median channel, not with the blanking-aware model). Results: results.

runLockedRadar.m (B5b)

A radar with PRF 400 Hz = 4·f0, one pulse per turn on the pulse flank: what excision leaves of it folds coherently into the profile. Stops if main's sky files do not match the parameters (checkSkyFiles, 13 Oct).

  1. Receiver runs: reference (no radar) and with the locked radar (0.1 µs and instant edges). Radar run − reference = the radar alone (the chain is linear).
  2. Per case: mask from the full data; reference, radar-only and full data all go through the same blanking, dedispersion, detection and fold with the same weights.
  3. Leftover L(φ) = folded radar-only power / channel baseline.
  4. TOA bias at −5 dB: full data − reference (same noise), cross-checked with reference + leftover.
  5. Bias at weak SNR: noise-free folds ρ·template + L through estimateTOA, ρ from −5 to −60 dB; the ρ where the bias reaches 1 µs.
Design choice: measure the leftover in baseline units, not as a TOA error

Alternative: measure the TOA error caused by the radar at −5 dB.

Why not: the pulsar is ~80,000× weaker at −54 dB than at −5 dB, so a TOA test at −5 dB says little about the target. The leftover in units of the noise baseline does not depend on the pulsar, and comparing it with the pulse height ρ gives the bias at any SNR from one run.

Cases are rows of caseList = [radar, excision, frequency guard, periodic mask]; radars: 0.1 µs edges, instant edges, and (B6-3) the 0.1 µs radar on a rotating antenna seen only through −35 dB sidelobes. Cases 9–12 compare excision with and without the periodic mask; runCases picks a subset, and only the radars it needs are simulated.

Results and the frequency-guard sweep: locked radar; the periodic mask: periodicRFI.
