Run scripts

The scripts in the PulsarSimMatlab folder. main.m runs one realization; the run*.m scripts are experiments that run the same stages many times and compare with the truth. All read their parameters from pipelineParams.m and must be run with MATLAB's current folder = PulsarSimMatlab.

Which front end the experiments use

runMonteCarlo, runSNRSweep and runH0 predate the channelized front end and always run the full-band path, whatever frontEnd says. runRFITest and runLockedRadar run the channel path. The channel path's statistics are validated by its unit tests (exact covariances, Monte Carlo with the exact noise model) rather than by these long runs.

Why each experiment writes its own files

A later main.m run with skipped stages reloads files from data/. If an experiment overwrote them with another noise realization, main would silently pick it up (checkConsistency does not check the noise seed). Separate folders make that impossible.

Never run two of these at once

Scripts and tests that share files (e.g. data/chan/) corrupt each other's data when run in parallel: an overlapping run once gave noise 72× the radiometer value (bugs and lessons #11).

main.m

Run control at the top (runStage.*, plots.*, closeFigures), then:

  1. paths and pipelineParams;, a disk estimate;
  2. sky (generator + dispersion) or reload; optional plotDispersionCheck;
  3. receiver (noise/RFI + IQ) or reload; checkConsistency;
  4. processing: full band (dedispersion + detection) or channels (channelizer → [detectRFI → blankChannels] → dedisperseChannels → detectChannels → [blankingWeights]); optional IQ and detection checks (full band);
  5. fold (with NoiseCoeffs or DataWeights on the channel path) or reload; optional fold check;
  6. TOAs, detection, good TOAs, validateTOA (all and good), the exact optimum (full band).

Printed reference for seed 43, −5 dB, L = 0.1 s: full band 9 TOAs, median σ 2.880 µs, SNR 93.4; channel path 8 TOAs, 2.943 µs, SNR 92.3 (with excision 2.956 µs, 91.9).

Why the stages can be skipped

The sky stage is by far the slowest (random numbers and a 25-million-tap filter at 4 GHz) and does not depend on the noise. Changing the SNR, RFI or processing only needs the later stages. Each skipped stage reloads its info, and checkConsistency warns when files on disk were made with other parameters.

runMonteCarlo.m validated

The pulsar signal is fixed (sky files from main.m); only the receiver noise changes: seeds seed + (1:nSeeds), default 10. The spread of TOAs between realizations is exactly what the error bars claim to describe, so the pooled z = (TOA − truth)/σ must be N(0,1).

  • Built-in check: seed 1 = main's noiseSeed, so its TOAs must equal main's.
  • Errors if the sky files do not match the parameters (T, L, f_in, seed, DM, band).
  • Full-band stage calls as in main.m, 'Verbose', false; validateTOA pools all TOAs.

Result (−5 dB, 90 TOAs): rms/pred 0.950 ± 0.075, χ²red 0.91, 72 % within 1σ.

Its blind spot

The pulsar realization is the same in every run, so its self-noise is identical everywhere and missing from the scatter. Fine at −5 dB (~4 % of the variance), wrong at high SNR. That is why runSNRSweep varies the pulsar too.

Why a very low SNR is not used as H0

−50 dB is not "no pulsar": it is a real small-antenna operating point that only needs long integrations. H0 must be a zero sky.

Results: validation record. Variant run on 6 Oct with nReal 20 and −20…−15 dB in 1 dB steps: the threshold sweep (results kept in data/mc/snrSweep_phaseDE.mat).

runH0.m validated

Many independent noise-only profiles to test the H0 side of detectPulsar and the noise covariance model behind it (and behind the TOA error bars).

  • nPass (100) passes, zero sky made once, receiver noise with seed seed + 10000 + i (no overlap with the sweeps), the same processing as main; 9 complete turns per pass.
  • Collects T0, Tmax, noiseRatio, the circular autocorrelation of each normProfile, and the model lag-1 correlation from weightX.
  • Exceedances at PFA 10⁻¹, 10⁻², 10⁻³; saves data/mc/h0Run.mat; figure.

Motivation: the phase E sweep gave T0 std 1.10 ± 0.075 under H0 and error-bar ratios of 1.03–1.06, all from the same 10 noise realizations: possibly a 5–10 % hole in the noise model. Outcome: T0 std 1.008 ± 0.024, lag-1 correlation 0.2484 vs 0.2501 modelled, nothing beyond lag 1. The noise model is complete; the earlier hint was a fluctuation of the shared realizations.

runRFITest.m (B4) validated

For each case (noise only; each source of rfiScenario alone; all five) the receiver stage runs with that RFI and main's noise seed (so the noise is the same in every case), then the channel path twice: without and with excision, both with optimal weighting. A table: blanked fraction, good TOAs, median SNR, median TOA error, rms/pred, median χ², total offset. Requires frontEnd = 'channels'.

Results: RFI excision.

Rotating radar cases (B5c-2, 8 Oct): cases 8–11 use the scenario radar on a rotating antenna (10 s scan, 39 ms beam): one beam passage centred in the file (−30 dB floor), and sidelobes only (beam 5 s away) at −25 / −30 / −35 dB. For pulsed sources the table adds, from the source's parameters (ground truth, validation only), the fraction of its pulses blanked in its own channels and the fraction of its energy in missed pulses. runCases picks a subset of the cases.

LTE cases (B5d-2, 8 Oct): cases 12–13: the 'noise' type, 20 MHz at 1472 MHz (inside LTE band 32), INR −10 and 0 dB. Results: receiver and excision limits.

Realistic scenario (B5e, 9 Oct): case 14 = rfiRealistic (~3 min); case 15 = the same with Inmarsat as ten narrow (200 kHz) carriers inside channels 105–114 instead of three wide blocks (~5 min), the worst case for the TOA error bars. A case can be given as {sources, label}. Since 9 Oct the excision path also runs periodicRFI when periodicMask is true, as main.m does (before: detectRFI only).

Per-channel noise check (B5e, every case; evaluation only): r = var/mean² of the off-pulse fold bins (more than 3 FWHM from the pulse) in a channel, over the median channel's (1 = behaves like the model). Two table columns: the number of channels with r > 1.1, and how much the TOA error bars are too small because of them, √(ΣF r/ΣF) − 1 with F = 1/ac² (the fit's channel weights). After the table, per run with excision: the channels with r > 1.1 or with flagged windows > 10× the expected false flags and > 3× the median channel's, with the sources covering them (ground truth, for labels only), and the periodic emitters found. Valid only when little is blanked (r compares with the median channel, not with the blanking-aware model). Results: results.

runLockedRadar.m (B5b)

A radar with PRF 400 Hz = 4·f0, one pulse per turn on the pulse flank: what excision leaves of it folds coherently into the profile.

  1. Receiver runs: reference (no radar) and with the locked radar (0.1 µs and instant edges). Radar run − reference = the radar alone (the chain is linear).
  2. Per case: mask from the full data; reference, radar-only and full data all go through the same blanking, dedispersion, detection and fold with the same weights.
  3. Leftover L(φ) = folded radar-only power / channel baseline.
  4. TOA bias at −5 dB: full data − reference (same noise), cross-checked with reference + leftover.
  5. Bias at weak SNR: noise-free folds ρ·template + L through estimateTOA, ρ from −5 to −60 dB; the ρ where the bias reaches 1 µs.
Why measure the leftover in baseline units

The pulsar is ~80,000× weaker at −54 dB than at −5 dB, so a TOA test at −5 dB says little about the target. The leftover in units of the noise baseline does not depend on the pulsar, and comparing it with the pulse height ρ gives the bias at any SNR from one run.

Cases are rows of caseList = [radar, excision, frequency guard, periodic mask]; radars: 0.1 µs edges, instant edges, and (B6-3) the 0.1 µs radar on a rotating antenna seen only through −35 dB sidelobes. Cases 9–12 compare excision with and without the periodic mask; runCases picks a subset, and only the radars it needs are simulated.

Results and the frequency-guard sweep: locked radar; the periodic mask: periodicRFI.
