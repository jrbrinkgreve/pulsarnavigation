Unit tests

Every function added since 6 October has a test in tests/ that checks it three ways: regression (bit-identical where nothing should change), algebra (code = independently computed formula) and physics (measured noise = predicted noise, within a predicted σ).

In short

Each test checks one function. Where the function gained an option, its default must still give the old output bit for bit. Its code must agree with an independently computed formula. And the noise it produces or models must match the prediction, within the scatter the prediction itself gives.

tests/runAllTests.m runs all 25 listed tests in one session (6–9 min), on their own frozen data. So a main.m run can never change what they check. A twenty-sixth, the slow testRFIChain, runs only when named.

Labels in the table below: blocks A (channelized front end), B (RFI excision), C (fast simulator) and D (motion, clock and navigation) were built in numbered steps (A1–A4, B1–B6, C1–C4, D1–D5); the roadmap lists them. "pre-A2" and similar mean "the code before that step".

How to run

run('tests/makeTestData.m')         % once: freeze the test data in data/test/ (~2.2 GB)
run('tests/testChannelizeIQ.m')     % one test
run('tests/runAllTests.m')          % all 25 unit tests, in order, summary at the end (6–9 min)
runAllTests("testRFIChain")         % the slow one, only when named (~2.5 h)

Run them from the PulsarSimMatlab folder. Every test is a function with its own workspace. It prints PASS/FAIL lines and its numbers, and tests can be run one after another in one MATLAB session.

runAllTests (13 Oct 2026) does exactly that:

  • it runs the tests that write the shared channel files first;
  • it runs each test in its own try/catch, so a failure does not stop the rest;
  • it ends with a table of PASS/FAIL, run time and the first line of each error, and raises an error if any test failed.

A subset: runAllTests(["testRfiNoise" "testRadarEdges"]), with tests/ on the path, run in dependency order. The demo*, exp* and make* files are not run. A new test*.m that is not yet in the list runs last, with a note. Slow tests (testRFIChain, ~2.5 h for its two cases) are skipped in the default run, printed as skipped, and run only when named.

Design choice: tests are functions, not scripts

Alternative: test scripts, which are quicker to write and leave their variables in the workspace for inspection.

Why not: as scripts they shared the base workspace: one test's onCleanup object was destroyed by the next test's assignment, its cleanup ran at once and changed the folder back, and the next test failed with "Unrecognized function 'pipelineParams'". It only showed when several tests ran in one session, the way Jasper runs them (bugs and lessons #11).

Order and shared files
  • The tests have their own frozen settings and data (since 13 Oct 2026). The settings are tests/testParams.m, used instead of pipelineParams: seeds 42 and 43, −5 dB, no RFI, L = 0.1 s, fLO 1.3 GHz, fs 800 MHz, f_out 1 MHz, nBin 2048, 128 × 3.125 MHz. The data are in data/test/, made once by tests/makeTestData.m from main.m's seed-43 files, after checking that they have that configuration.
    So main.m runs with other settings, or edits to pipelineParams, no longer change what the tests check. Before, a main.m run with another SNR or RFI rewrote the tests' input (data/test_rx_IQ.dat, data/chan/). That broke the bit-for-bit regressions, or silently changed the data. On 13 Oct all 14 tests of that day passed on the frozen data (Jasper's run of runAllTests, 6.8 min).
  • testDedisperseChannels and testDetectChannels rewrite the channel files in data/test/chan/, with the same contents. A single test that needs them finds them there.
  • The make*Reference.m scripts are not tests: they froze outputs of old code (at a named commit) for the regression checks. Do not rerun them with new code.
  • Never run two test sessions at once: they share data/test/chan/ and their tempdir folders. main.m at the same time is fine (it does not touch data/test/).
  • A result counts as validated only after Jasper's own run.

The tests

Design choice: pass criteria from the predicted σ

Alternative: a tolerance chosen by hand, such as "within 5 %".

Why not: a guessed tolerance proves nothing: it may be loose enough to hide a real error, or so tight that a correct code fails by chance. Each physics check therefore first predicts the scatter of what it measures (for example the variance of a variance estimate) and passes when the measurement lies within a few of those σ. The algebra checks compare with an exact formula, to rounding error.

testChannelizeIQ

The channelizer is exact: tones, noise and real data all come out as the formulas say.

  1. Tones at, beside and far from channel centres. Every output sample equals A·eiφ·Hc(Δf)·ei2πΔf·t, to 2.7·10⁻⁷. This one test pins down the frequency mapping (which channel), the LO phase, the timing and the gain. The far tone checks the stopband: −80.2 dB.
  2. White noise (2²³ samples). The channel power divided by Σh² is 1.0007, and the passband level 1.0004. The noise model depends on this gain.
  3. Real data (seed 43). The channel band powers add up to the IQ band power, to 1.00007. So there are no gaps and no double counting (Parseval).

testDedisperseChannels

Per-channel dedispersion is exact, and agrees with the full band.

  1. Regression. The full-band applyInverseDispersion, with the new option off, gives test_IQ_dedispersed.dat bit for bit.
  2. Commutation. channelize(dedispersed) against dedisperse(channelized): correlation ≥ 0.999993, phase ≤ 1.2·10⁻⁵ rad, power 1 ± 3·10⁻⁵. Both are linear filters, so the order must not matter. This proves the chirps, the delays between channels and the phases.
  3. End to end. The channel and full-band TOAs differ by the predicted scatter, σ·√(2(1−ρ)) with ρ = 0.979. This is tested as a χ², which falls in the 99.8 % range.
  4. Time-bin noise. The variance is 0.884, against 0.888 ± 0.005 predicted; the lag-1 correlation is 0.054, against 0.052. This showed that the narrow-channel effect is real.

expBlankingVariance (experiment 3a)

This experiment showed that no simple rule gives the variance of a blanked bin, and led to exact per-bin weights.

The setup: noise only, in the bottom channel, at DM 5 and DM 100, with three masks:

  • a radar, 4 µs at 373 Hz;
  • random 50 µs blanks, 10 % of the data;
  • 1 ms gaps every 5 ms, 20 % of the data.

The mean P/W is 1 in every valid-fraction group. The measured variance divided by the exact one is 1 ± 0.002, over ~10⁶ bins. The "exact" value comes from the mask convolutions, which were checked against a direct 2n×2n matrix to 7·10⁻⁸. The simple w² and w models are off by up to ±45 %. That result killed the "g(w)" idea.

testDetectChannels

The narrow-channel noise model is exact, and matches real data.

  1. powerCovariance, computed from the spectrum, equals the statistics of the actual dedispersion impulse response, to 6·10⁻¹⁰.
  2. The interleaved [128 × nBins] file equals detectPower per channel: bit-identical rows.
  3. Folding the 128-channel file and summing equals folding the summed power, to 1.2·10⁻⁸.
  4. Measured on real data: V is 0.8866, against 0.8877 ± 0.0006 predicted, and X₁₋₃ match. The variance of 5-bin sums is 0.9685, against 0.9692 predicted; independent bins would give 1.

  2. Algebra. An awkward synthetic geometry (f0 100.3 Hz, F1 −0.5 Hz/s, 4096 bins, chunks of 1000) with exaggerated coefficients. weight2 and weightX equal AᵀCA from the explicit assignment matrix, to 6·10⁻¹⁶.
  3. Physics. On 128-channel data, the measured phase-bin variance and lag covariances, against each model:

  5. Random weight streams (3 channels, 10 % zeros). weight equals AᵀW, and weight2 and weightX equal AᵀCA per channel, to 7·10⁻¹⁶. A bin with W = 0 adds no power.

testChannelTOA

The channel-aware TOA fit and detector equal their explicit formulas, and keep the single-channel results.

  1. estimateTOA on a single channel gives the pre-A2 reference outputs bit for bit, in five cases.
  2. phaseErr = √(dᵀΣd)/|C″| and ampErr match the full covariance built channel by channel, to 4·10⁻¹⁶. This was checked with 128 channels and 3 lags, and with fake blanking and excluded channels.
  3. Physics: the 128-channel fold and the summed power give the same TOAs; blanked and unblanked are consistent.
  4. detectPulsar: regression bit for bit.
  5. T0, normProfile and Tmax equal the explicit full H0 covariance formulas.
  6. noiseRatio is 1 within 4σ on the channel path, blanked and unblanked.
  7. Resolution warning (9 Oct). Six combinations of time bin and NBin, from (0.96 µs, 2048) to (200 µs, 32), and (0.96 µs, 24). binResolution = max(binDt·f₀, 1/NBin), and the warning comes exactly when it exceeds templateWidth/10 (/5 until 20 Oct).
    templateWidth is the spectral width, 0.459/kt (since 20 Oct). For a Gaussian it equals the FWHM, to 10⁻³. For a two-component template, and for B0329+54's five components, it equals the value from their analytic harmonics, Σi ai σi exp(−2π²σi²k² − 2πikci), to 10⁻⁶. For B0329+54 that is 0.00774 turns.

testBlankingWeights

The blanking weights are exact and consistent, and give an unbiased fold end to end.

  1. Exactness. W, V and X(1..7) against the direct covariance H·diag(keep)·H′, for 221 bins in channels 1, 64 and 128, with blanks of 1–3001 samples: 3·10⁻⁸.
  2. Consistency. An empty mask gives the NoiseCoeffs fold. Bins far from blanks get the unblanked constants. A messy mask gives the same result as a tidy one. (2e) The channel autocorrelation from the prototype equals the measured one.
  3. End to end. Voltages blanked before dedispersion, with a zoo of masks that includes a phase-locked 400 Hz radar and blanks on the pulse. The means are unbiased in every W group, and the noise is as modelled in every valid-fraction group. Channel exclusion follows the rule, the TOAs are consistent, and the noise ratio is 1.
  4. Long time bins (12 Oct). Bins of 1401 samples with Lmax 1, so that the lag range reaches channel 128's filter (2802 samples), and qτ is a single number at the last lag. 9 bins against the direct covariance: 2.8·10⁻⁸. The code before the fix fails this case: it would build an M×M array of 4096 GB.

testOptimalTOA

Optimal weighting equals FFTFIT for one channel, its error bars equal the explicit sandwich, and it is unbiased and more precise than equal weighting.

  1. The default gives the pre-A2 outputs bit for bit.
  2. One channel with uniform weights: τ equals FFTFIT, to 1.7·10⁻¹⁶ turns.
  3. 128 channels, unblanked and fake-blanked: τ maximizes N/√Dn, b and ac are the weighted least-squares values, and the errors equal the explicit sandwich.
  4. Monte Carlo, 800 profiles per level with the exact covariance of 64 fake-blanked channels. It is unbiased, with pulls of standard deviation 1.006–1.037. The scatter of optimal weighting is 0.955–0.963 of equal weighting's, as predicted.
  5. Fake-blanked data: optimal weighting uses all 128 channels, equal weighting 118. Their TOAs agree within −0.006 ± 0.352 µs.
  6. Tests 6–10, detection. The default is bit for bit. The explicit H0 matrices match to ≤ 10⁻¹⁵. An H0 Monte Carlo gives false-alarm rates of 0.054 (known phase) and 0.051 (unknown phase), against a design of 0.05 ± 0.008. Under H1, 0.914 of the profiles are detected, against 0.910 in theory. Blanked data are consistent.

testDetectRFI

The detector flags noise at the design rate, does not trip on the pulsar, catches each RFI type, and handles narrow carriers (more on the excision page).

The test uses its own 0.05 s channel files, noise only and noise + RFI, made through the real receiver chain with the same noise seed. Their difference is the RFI alone.

  1. False flags on noise at the design rates.
  2. The −5 dB pulsar's flags on and off the pulse, as predicted for each window length.
  3. Radar, impulses, carrier and GNSS, scored against the RFI-only signal. (3d) The frequency guard: the mask is the own detections plus the strong events copied to ±7 channels.
  4. (21 Oct) Per-channel thresholds, with three 200 kHz noise carriers and a +20 dB radar on one of them. At PFA 10⁻³ the carrier channels without the radar flag 0.96–1.15 × the expected windows with their own thresholds, against 1.8–63 × with the white ones. At the default PFA they flag 1 and 0 windows, instead of 432 and 386. All 19 radar pulses on the carrier are still blanked. Channels away from the RFI give the old mask bit for bit, and pure noise gets no thresholds of its own. Tests 1–3 are unchanged, except that 3d's unguarded blanked fraction went from 0.6487 to 0.6484 %: the constant-envelope channels flag slightly less.

Claude's run of 21 Oct and Jasper's run of 22 Oct: all passed. The test uses its own temporary folder per run.

testRadarEdges

The radar edges are modelled exactly, and change nothing when switched off.

  1. RiseTime 0 gives the pre-B5a output bit for bit.
  2. The defaults (0.1 µs for 'pulsed') apply, and invalid values are refused.
  3. The radar alone equals an independent formula, to 10⁻⁷. The envelope is 0.500 at the nominal edge. The energy equals a²/2·(PW − RiseTime/4), to 10⁻⁵.
  4. Spectrum: the energy beyond 10, 25 and 50 MHz matches 1/(π²F·PW) for instant edges, and the half-sine edge model for 0.1 µs edges.

testRfiGating

The antenna rotation scales each pulse exactly as the gain says (more on the receiver page):

  • no rotation gives the pre-B5a reference bit for bit;
  • invalid rotations are refused;
  • a radar and a carrier pass through two beam passages. The energy with rotation, divided by the energy without, equals g(t) averaged over each pulse, to 10⁻⁵.

testPeriodicRFI

The periodic mask finds no false emitters in noise or impulses, finds the radar, and blanks the weak sidelobe pulses it cannot see.

The test uses its own 0.05 s channel data through the receiver chain, with the same noise in every run. So a run minus the noise-only run is the RFI alone. It is scored with the sources' parameters.

  1. Noise only: no emitter.
  2. Impulses at 1000/s: no emitter.
  3. Scenario radar: PRF 372.9992 ± 0.0018 Hz (true 373). The predicted pulse times are within 0.4 samples of the truth, and all pulses are blanked.
  4. A rotating radar seen only through −35 dB sidelobes. It is found from the 42 % of its pulses that detectRFI catches. With the prediction, 100 % are blanked, and the radar energy left drops from 0.48 to 8.8·10⁻⁶.

testGeneratePulsarSignal

The generator writes exactly the pulsar it claims to, independent of the block size, with clean seed handling.

This tests stage 1, the synthetic pulsar (13 Oct 2026). The ground truth is computed independently: the envelope as an exact periodic sum of 21 Gaussian images, not the generator's nearest pulse.

  1. Format and ground truth, with binary-exact numbers, so that the 13th pulse centre lies on the last sample.
  2. The folded mean of x² in 1 µs bins against A²·G, with the exact per-bin σ (var(x²) = 2(A²G)² for Gaussian x). The residuals have mean 0 and standard deviation 1. The pulse centre is right to ±17 ns, and the width to ±0.1 % (FWHM 49.92 µs for 50 µs nominal).
  3. 'amplitude' mode: the power FWHM is the nominal one / √2.
  4. The widest real pulses (20 % duty; pulsars stay below ~20 %), in all bins. Halfway between pulses the neighbours' tails overlap, which checks the generator's sum over neighbours. A copy without that sum fails this check.
  5. The same seed gives identical data. Other block sizes give bit-for-bit identical data (randn drawn in pieces equals one piece). A scales exactly (normal floats). The global random generator is untouched. The clock seed reproduces the file.
  6. Bad inputs are refused. 25 % duty warns (wider than real pulsars); 20 % does not.
  7. A pulse of three Gaussian components (option 'Components'), against the exact sum of the components. The residuals have mean 0 and standard deviation 1, and the pulse's centroid and width match the model. One centred component gives the single Gaussian bit for bit, and 'amplitude' mode is refused with components.

The noise-like RFI source has the right power, a flat band and Gaussian statistics, and changes nothing else (more on the receiver page).

  2. A block size of 10⁶ + 3 gives the same output as one block, bit for bit.

testSimulateFold (20 Oct)

The fast simulator reproduces foldProfile's conventions and the validated noise model: for one channel and for 128, with RFI profiles, passes, scintillation, adaptive sub-ints, two polarizations, multi-component profiles and noise calibration. It needs no data files; it works on synthetic power in tempdir.

One channel

  1. Conventions. A noise-free synthetic power series (the generator's periodic Gaussian, erf-averaged over 1 µs bins, pulses at phase 0.0123) is folded by foldProfile, and compared with simulateFold's mean profile. The largest difference is 5.3·10⁻⁵ of the pulse peak; the limit is 5·10⁻⁴, and a one-bin shift would give ~10⁻². All of foldProfile's fold, sub-int and info fields are present.
  2. Noise with asymptotic weights, 4000 sub-ints: variance 0.9999, neighbour correlation 0.2497 (expected 0.25), lag 2 −0.0002. With a 0 dB pulse, the residuals in the bright bins have variance 0.998 (self-noise ∝ m²).
  3. Weights copied from the foldProfile fold: variance 0.9996; correlation minus model −0.0002.
  4. foldToTOA on simulated folds at −5 dB: 400 TOAs, SNR 93.5, σ 2.907 µs, pulls with mean +0.10 and standard deviation 0.997 (±0.035). Under H0, with 3000 sub-ints: T0 mean +0.026, standard deviation 1.000.
  5. Speed: 20 h in 60 s sub-ints (1200 sub-ints) takes 0.05 s.

Channels

  1. The closed-form weights with correlated time bins agree with foldProfile with NoiseCoeffs, to 2·10⁻⁵ relative.
  2. 16 channels: lag correlations 0.2583, 0.0012 and 0.0002, against the model's 0.2586, 0.0012 and 0. The channels are independent.
  3. 128 channels at −5 dB with optimal weighting: pull standard deviation 1.005, and σ within 1 % of the one-channel full-band fold.

RFI profile

  1. A synthetic 8-channel profile. The channel means equal the levels, and the weights equal the clean model × the valid fraction. The noise relative to the observer's model is as set, per channel: 1.301 for a narrowed channel, 0.361 for a strong carrier.

Observing schedule

  1. One pass gives the nTurns interface bit for bit. Two passes with 10 s sub-ints give 3 + 3 sub-ints, with every turn inside its pass, and the expected turnRef and tRef. The TOAs are valid on the absolute time axis.

Scintillation

  1. 'FluxScale' 0.25 gives a fitted amplitude ratio of 0.250 ± 0.001. The drawn field has mean 0.97, variance 0.92, and P(F < 0.1) = 0.097 (exponential: 0.095). Its intensity correlation is 0.363 at the scintle time (1/e = 0.368), and 0.490 at the scintle bandwidth (0.5). The band average keeps mean 1, with variance 0.25. 2 MHz scintles in 128 channels of 3.125 MHz give mean 1.001 and variance 0.801, against 0.791 from the channel average of the intensity ACF. (This is the grid fix of 20 Oct; one point per channel gave 1.) 'Scintillation', [] is off, bit for bit.

Adaptive sub-ints

  1. mergeSubints of the one-turn fold in groups of 5 equals the 5-turn foldProfile fold, to 10⁻¹². adaptiveSubints at −25 dB closes 109 groups at T0 ≥ 7 (median 36 turns), with TOA pulls of mean +0.15 and standard deviation 0.975. With 2 s scintles it closes 147 groups (median 7), with pulls −0.08 and 1.04, and bright stretches close sooner. No group crosses a gap between passes.

Dual polarization and groups over gaps (20 Oct)

  1. 'NPol', 1 equals no option, bit for bit, also with an RFI profile. 'NPol', 2 equals 'Bnoise' × 2 exactly. With the RFI profile and NPol 2, the variance against the observer's model with Bn × 2 is the profile's (1.301, 0.361, ~1).

Multi-component profile (20 Oct)

  1. The template of one component, [1 0 FWHM], equals the single Gaussian bit for bit, and simulateFold's to 3·10⁻¹⁶. Three components agree with foldProfile on a noise-free series, within 8.6·10⁻⁵ of the peak. Per-channel noise calibration (20 Oct)

  1. 'ObserverNoise', 'model' equals the default bit for bit. 'measured' draws the same noise, and gives the fold the measured coefficients. The variance against the fold's own model is then 1.00 in every channel of test 9's profile, instead of 1.30 and 0.36. The truth of a moving receiver

  1. 'PhaseOffset' as a function of time. A constant function equals the scalar, bit for bit. A function that returns the wrong number of values is refused (Claude's run of 21 Oct, Jasper's run of 22 Oct).

testRFIModel (20 Oct)

The RFI model recovers known statistics from synthetic data, and folds drawn from the measured profile match real folds. The test also shows that the comparison detects what a profile misses.

testRFIChain (slow, 20 Oct)

It repeats testRFIModel's comparison on the voltage chain's real RFI and excision. Both cases now pass: the realistic scenario and the narrow Inmarsat carriers. The narrow case first had two failures at 1 turn. They were diagnosed (below), and the two fixes, per-channel detectRFI thresholds and 30 lags, removed them.

How it works. For each case it makes one pulsar-free 1 s chain run, as runRFIProfile does: beam passages outside the run, its own noise seed, and the DM from pipelineParams. The default cases are the realistic scenario and the narrow Inmarsat carriers; noise only is on request. The detected power is split in two halves. Half A gives the RFI profile. Half B is folded by foldProfile with the excision weights (NBin 1024, 1 and 10 turns per sub-int). It is compared, channel by channel, with 60 simulateFold realizations of the half-A profile.

The checks:

  • the level;
  • the noise relative to the observer's model: the core check. Correlations beyond the measured lags, or slow variation, would show as an excess, larger at 10 turns;
  • the neighbour correlation;
  • kurtosis and 4σ tails, against the clean channels of the same run. A phase bin of one turn averages only ~30 complex samples, so the detected power is gamma-like: excess kurtosis ~0.17. The Gaussian simulation does not draw this, and it vanishes for sub-ints of minutes;
  • the flatness over phase of the mean profile and of the blanked fraction, against random rotations of the real sub-ints.

A channel is flagged at |z| > 5 (~1 % false flags per case). Flagged channels are listed with their frequency, so a FAIL in the realistic case points at where the second-moment model breaks. The test is not in runAllTests' default run; run it with runAllTests("testRFIChain"). It takes ~75 min per case, 5–8 GB of memory, and ~40 GB of temporary files.

Diagnosis of the narrow-Inmarsat failures (21 Oct)

The scratch script diagNarrow ran the same chain with and without excision, with lags to 30 in both halves. It split the half-B fold into phase bins without and with blanking, and simulated from half A, from half B, and from half B with 30 lags.

  1. The neighbour-correlation FAIL is the lag-7 cut-off. The 200 kHz carriers' power correlation has a sidelobe at lags 7–20, holding 5–7 % of the long-run noise. Without excision, the real 0.29–0.305 is matched by the 30-lag simulation, not by 7 lags (0.28).
  2. The noise excess (+2.5–5.6 % in the carrier channels) is data-dependent blanking. detectRFI's false flags (~1400 windows per carrier channel, against 2.4 expected) cut the carriers' power peaks. The valid bins next to a cut keep the peak's correlated shoulders. Phase bins without blanking agree with the simulation within ±1 %. Bins with blanking (~55 %) are +4–9 % high. Without excision, real and simulated agree within ±1 %. The halves are stationary (V within 1 %).
    The same happens, smaller, in the partly covered LTE channels 81 and 94 (+3 %, only in blanked bins), and in channel 61's 1.9 % blanked bins (2.7× noisier: its heavy tails).

The observer's noise calibration absorbs both (on the chain: χ² 1.24 → 0.99). Since 21 Oct the per-channel detectRFI thresholds remove these false flags (excision), and the test's half-A profile, like runRFIProfile, uses 30 lags.

expSamplingRate (experiment, 9 Oct)

A higher post-detection rate f_out does not help: the information is set by bandwidth × time.

The question came from a meeting: a matched filter at 100 kHz looks less noisy than at 1 kHz, so should a higher f_out help? Two experiments with 300 trials answered it. Every measured SNR is within 4σ of its prediction.

  1. A known pulse (FWHM 5 ms) in white noise. With the same σ per sample at every rate, the SNR grows as √fs (4.9 → 170), because the noise PSD the filter sees, 2σ²/fs, drops. With a fixed physical PSD and integrate-and-dump, as in the pipeline, the SNR is 5.0 at every rate. Keeping one sample per output (aliasing) grows back to 5.0 only at the analog rate. In all cases the measured SNR equals √(2E/N0), with the N0 the filter sees.
  2. A noise-like pulse with the square law. Square, then average (the pipeline) sits at the radiometer bound a√(B∫(g−⟨g⟩)²dt) for every f_out. Square then keep one sample, or average the voltages then square: both grow as √f_out, and reach the bound only at f_out = B.

The bound is set by B·T, not by the post-detection rate. Full discussion: logs/2026-10-09_fout-study.md.

demoBinningMatchedFilter (demo, 9 Oct)

A script for explaining the binning, run section by section. It shows that averaging into bins loses almost nothing, while keeping one sample per bin loses a lot.

A noise-like pulse (complex, 100 MHz, P 10 ms, FWHM 0.5 ms, peak 3.4 % of the noise) is detected, and then matched-filtered in three ways:

Matched filtermeasured SNR (100 trials)predicted
(1) at 100 MHz21.520.0
(2) after averaging into 10 kHz bins21.419.9
(3) after keeping one sample per 10 kHz bin0.230.20

Binning loses only the 0.5 % smearing of a 100 µs bin, and is about 130× faster: 0.58 ms including the binning, against 78 ms via FFT (timeit). A direct convolution at the full rate would take ~10¹⁴ operations. Decimation without averaging loses √10000 = 100× in SNR.
