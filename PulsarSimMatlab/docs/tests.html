Unit tests

Every function added since 6 October has a test in tests/ that checks it three ways: regression (bit-identical where nothing should change), algebra (code = independently computed formula) and physics (measured noise = predicted noise, within a predicted σ).

In short

Each test checks one function. Where the function gained an option, its default must still give the old output bit for bit. Its code must agree with an independently computed formula. And the noise it produces or models must match the prediction, within the scatter the prediction itself gives. tests/runAllTests.m runs all fourteen in one session (6–9 min) on their own frozen data, so a main.m run can never change what they check.

How to run

run('tests/makeTestData.m')         % once: freeze the test data in data/test/ (~2.2 GB)
run('tests/testChannelizeIQ.m')     % one test
run('tests/runAllTests.m')          % all 14 unit tests, in order, summary at the end (6–9 min)

From the PulsarSimMatlab folder. Every test is a function (own workspace), prints PASS/FAIL lines and its numbers, and can be run one after another in one MATLAB session. runAllTests (13 Oct 2026) does exactly that: the tests that write the shared channel files first, each test in its own try/catch (a failure does not stop the rest), then a table PASS / FAIL, run time and the first line of each error, and an error at the end if any test failed. A subset: runAllTests(["testRfiNoise" "testRadarEdges"]) (with tests/ on the path; run in dependency order). Not run: the demo*, exp* and make* files; a new test*.m that is not in its list runs last, with a note.

Design choice: tests are functions, not scripts

Alternative: test scripts, which are quicker to write and leave their variables in the workspace for inspection.

Why not: as scripts they shared the base workspace: one test's onCleanup object was destroyed by the next test's assignment, its cleanup ran at once and changed the folder back, and the next test failed with "Unrecognized function 'pipelineParams'". It only showed when several tests ran in one session, the way Jasper runs them (bugs and lessons #11).

Order and shared files
  • The tests have their own frozen data and settings (13 Oct 2026): tests/testParams.m (used instead of pipelineParams: seed 42/43, −5 dB, no RFI, L = 0.1 s, fLO 1.3 GHz, fs 800 MHz, f_out 1 MHz, nBin 2048, 128 × 3.125 MHz) and data/test/, made once by tests/makeTestData.m from main.m's seed-43 files (it checks they are that configuration first). So main.m runs with other settings, or edits to pipelineParams, no longer change what the tests check. Before, a main.m run with another SNR or RFI rewrote their input (data/test_rx_IQ.dat, data/chan/) and broke the bit-for-bit regressions or silently changed the data. All 14 tests pass on the frozen data (Jasper's run of runAllTests, 13 Oct, 6.8 min).
  • testDedisperseChannels / testDetectChannels rewrite the channel files in data/test/chan/ (the same contents); a single test that needs them finds them there.
  • The make*Reference.m scripts are not tests: they froze outputs of old code (at a named commit) for the regression checks. Do not rerun them with new code.
  • Never run two test sessions at once: they share data/test/chan/ and their tempdir folders. main.m at the same time is fine (it does not touch data/test/).
  • A result counts as validated only after Jasper's own run.

The tests

Design choice: pass criteria from the predicted σ

Alternative: a tolerance chosen by hand, such as "within 5 %".

Why not: a guessed tolerance proves nothing: it may be loose enough to hide a real error, or so tight that a correct code fails by chance. Each physics check therefore first predicts the scatter of what it measures (for example the variance of a variance estimate) and passes when the measurement lies within a few of those σ. The algebra checks compare with an exact formula, to rounding error.

testChannelizeIQ

  1. Tones at, beside and far from channel centres: every output sample equals A·eiφ·Hc(Δf)·ei2πΔf·t to 2.7·10⁻⁷. One test pins down frequency mapping (which channel), LO phase, timing and gain. The far tone checks the stopband (−80.2 dB).
  2. White noise (2²³ samples): channel power / Σh² = 1.0007, passband level 1.0004. The noise model depends on this gain.
  3. Real data (seed 43): Σ channel band powers / IQ band power = 1.00007 (Parseval: no gaps, no double counting).

testDedisperseChannels

  1. Regression: full-band applyInverseDispersion with the new option off = test_IQ_dedispersed.dat bit for bit.
  2. Commutation: channelize(dedispersed) vs dedisperse(channelized): correlation ≥ 0.999993, phase ≤ 1.2·10⁻⁵ rad, power 1 ± 3·10⁻⁵. Both are linear filters, so the order must not matter; this proves chirps, inter-channel delays and phases.
  3. End to end: channel vs full-band TOAs; differences scatter as predicted (σ·√(2(1−ρ)), ρ = 0.979), tested as a χ² in the 99.8 % range.
  4. Time-bin noise: variance 0.884 vs 0.888 ± 0.005 predicted, lag-1 correlation 0.054 vs 0.052. This showed the narrow-channel effect is real.

expBlankingVariance (experiment 3a)

Noise only, bottom channel, DM 5 and DM 100, three masks (radar 4 µs at 373 Hz; random 50 µs blanks, 10 %; 1 ms gaps every 5 ms, 20 %). Mean: P/W = 1 in every valid-fraction group. Variance: measured / exact = 1 ± 0.002 over ~10⁶ bins, "exact" from the mask convolutions (checked against a direct 2n×2n matrix to 7·10⁻⁸). The simple w² and w models are off by up to ±45 %: the result that killed the "g(w)" idea and led to exact per-bin weights.

testDetectChannels

  1. powerCovariance (from the spectrum) = statistics from the actual dedispersion impulse response, to 6·10⁻¹⁰.
  2. Interleaved [128 × nBins] file = detectPower per channel, bit-identical rows.
  3. Folding the 128-channel file and summing = folding the summed power (1.2·10⁻⁸).
  4. Measured on real data: V 0.8866 vs 0.8877 ± 0.0006; X₁₋₃ match; variance of 5-bin sums 0.9685 vs 0.9692 (independent bins would say 1).

testFoldWeights

  1. Regression: without new options the four reference folds bit for bit (the info's sourceFile by file name only, since the inputs moved to data/test/).
  2. Algebra: awkward synthetic geometry (f0 100.3 Hz, F1 −0.5 Hz/s, 4096 bins, chunks of 1000), exaggerated coefficients: weight2/weightX = AᵀCA from the explicit assignment matrix, to 6·10⁻¹⁶.
  3. Physics: 128-channel data, measured phase-bin variance and lag-1/2 covariance: new model −1.4σ / +0.6σ / −0.1σ, old model −13.1σ / +5.9σ.
  4. Constant weight file = NoiseCoeffs fold bit for bit (two code paths, one answer).
  5. Random weight streams (3 channels, 10 % zeros): weight = AᵀW, weight2/weightX = AᵀCA per channel to 7·10⁻¹⁶; a W = 0 bin adds no power.
  6. Fake blanking (15 % random + phase-correlated at 0.30–0.36): weighted mean unbiased (−0.0019 ± 0.0009) while the naive fold is −0.574 off as predicted; noise as modelled.
  7. Coverage warning (9 Oct): 10.08 µs bins with NBin 2048 and 1 turn per sub-int, linear and nearest, leave phase bins empty (coverage 0.966 / 0.483) → warning. NBin 512, 0.96 µs bins, or 10 turns per sub-int fill every bin → no warning. Passes when the warning comes exactly when the fold itself has empty bins.

testChannelTOA

  1. estimateTOA single-channel = pre-A2 outputs bit for bit (five cases).
  2. phaseErr = √(dᵀΣd)/|C″| and ampErr with the full covariance built channel by channel (128 channels, 3 lags; and fake blanking with excluded channels): to 4·10⁻¹⁶.
  3. Physics: 128-channel fold vs summed power: same TOAs; blanked vs unblanked consistent.
  4. detectPulsar regression bit for bit.
  5. T0, normProfile, Tmax = explicit full H0 covariance formulas.
  6. noiseRatio = 1 within 4σ on the channel path, blanked and unblanked.
  7. Resolution warning (9 Oct): six (time bin, NBin) cases from 0.96 µs / 2048 to 200 µs / 32 and 0.96 µs / 24: binResolution = max(binDt·f₀, 1/NBin) and the warning exactly when it exceeds templateWidth/5. templateWidth: Gaussian = FWHM (10⁻³); with a narrower second component, that component's width at half the global maximum (analytic, 10⁻²).

testBlankingWeights

  1. Exactness: W, V, X(1..7) vs the direct covariance H·diag(keep)·H′ for 221 bins (channels 1, 64, 128; blanks 1–3001 samples): 3·10⁻⁸.
  2. Consistency: empty mask = A1a fold; far bins = unblanked constants; messy mask = clean mask; (2e) channel autocorrelation from the prototype = measured.
  3. End to end: voltages blanked before dedispersion with a zoo of masks including a phase-locked 400 Hz radar and blanks on the pulse: means unbiased per W group, noise per valid-fraction group, channel exclusion as the rule says, TOAs consistent, noise ratio 1.
  4. Long time bins (12 Oct): 1401-sample bins with Lmax 1, so the lag range reaches channel 128's filter (2802 samples) and qτ is a single number at the last lag. 9 bins vs the direct covariance: 2.8·10⁻⁸. The pre-fix code fails this case (an M×M array of 4096 GB).

testOptimalTOA

  1. Default = pre-A2 bit for bit.
  2. One channel, uniform weights: τ = FFTFIT to 1.7·10⁻¹⁶ turns.
  3. 128 channels (unblanked, fake-blanked): τ maximizes N/√Dn, b and ac = WLS, errors = explicit sandwich.
  4. Monte Carlo, 800 profiles per level with the exact covariance of 64 fake-blanked channels: unbiased, pull std 1.006–1.037, scatter optimal/equal 0.955–0.963 as predicted.
  5. Fake-blanked data: optimal uses all 128 channels (equal 118); TOAs equal within −0.006 ± 0.352 µs.
  6. Tests 6–10, detection: default bit for bit; explicit H0 matrices ≤ 10⁻¹⁵; H0 Monte Carlo false alarms 0.054 / 0.051 (design 0.05 ± 0.008); H1 detected 0.914 vs theory 0.910; blanked data consistent.

testBlankChannels

1727 mask rows (5.2 % blanked): masked samples exactly 0, others bit-identical; merge/clip cases; block size independence; empty mask → byte-identical copies; dedisperseChannels on the result changes only blanked channels, only within the filter reach.

testDetectRFI

Own 0.05 s noise-only and noise + RFI channel files through the real receiver chain with the same noise seed (difference = RFI alone). (1) False flags on noise at the design rates; (2) the −5 dB pulsar's on/off-pulse flags as predicted per window size; (3) radar, impulses, carrier and GNSS scored against the RFI-only signal; (3d) the frequency guard: mask = own detections + strong events copied to ±7 channels.

testRadarEdges

(1) RiseTime 0 = the pre-B5a output bit for bit. (2) Defaults (0.1 µs for 'pulsed'), invalid values refused. (3) Radar alone = an independent formula to 10⁻⁷; envelope 0.500 at the nominal edge; energy = a²/2·(PW − RiseTime/4) to 10⁻⁵. (4) Spectrum: energy beyond 10/25/50 MHz matches 1/(π²F·PW) for instant edges and the half-sine edge model for 0.1 µs edges.

testRfiGating

No rotation = pre-B5a reference bit for bit; invalid rotations refused; radar and carrier through two beam passages: energy with/without rotation = g(t) averaged over each pulse to 10⁻⁵.

testPeriodicRFI

Own 0.05 s channel data through the receiver chain, the same noise in every run, so a run minus the noise-only run is the RFI alone; scored with the sources' parameters. (1) Noise only: no emitter. (2) Impulses at 1000/s: no emitter. (3) Scenario radar: PRF 372.9992 ± 0.0018 Hz (true 373), predicted pulse times within 0.4 samples of the truth, all pulses blanked. (4) Rotating radar seen only through −35 dB sidelobes: found from detectRFI's 42 % of the pulses; with the prediction 100 % blanked, radar energy left 0.48 → 8.8·10⁻⁶.

testGeneratePulsarSignal

Stage 1, the synthetic pulsar (13 Oct 2026). The ground truth is computed independently: the envelope as an exact periodic sum of 21 Gaussian images, not the generator's nearest pulse. (1) Format and ground truth, with binary-exact numbers so the 13th pulse centre lies on the last sample. (2) The folded mean of x² in 1 µs bins against A²·G, with the exact per-bin σ (var(x²) = 2(A²G)² for Gaussian x): residuals mean 0 / std 1, pulse centre to ±17 ns, width to ±0.1 % (FWHM 49.92 µs for 50 µs nominal). (3) 'amplitude' mode: power FWHM / √2. (4) The widest real pulses (20 % duty; pulsars stay below ~20 %), all bins: halfway between pulses the neighbours' tails overlap, which checks the generator's sum over neighbours (a copy without it fails this check). (5) Same seed identical; other block sizes bit for bit identical (randn drawn in pieces = one piece); A scales exactly (normal floats); global RNG untouched; the clock seed reproduces the file. (6) Bad inputs refused; 25 % warns (wider than real pulsars), 20 % does not.

testRfiNoise

(1) The other RFI types = the pre-B5a reference bit for bit. (2) Block size 10⁶ + 3 = one block bit for bit. (3) Power = INR × the in-band receiver noise within 4σ of 1/√(B·T): 0.9945 (σ 0.0045). (4) Spectrum flat in band (level 1.0078 of power/bandwidth), out of band ≤ 2·10⁻⁷. (5) Kurtosis 3.004 (Gaussian 3, σ 0.016).

expSamplingRate (experiment, 9 Oct)

Question from a meeting: a matched filter at 100 kHz looks less noisy than at 1 kHz, so should a higher f_out help? Two experiments, 300 trials, every measured SNR within 4σ of its prediction. (1) Known pulse (FWHM 5 ms) in white noise: with the same σ per sample at every rate the SNR grows as √fs (4.9 → 170), because the noise PSD the filter sees, 2σ²/fs, drops; with a fixed physical PSD and integrate-and-dump (the pipeline) it is 5.0 at every rate; keeping one sample per output (aliasing) grows back to 5.0 only at the analog rate. Measured = √(2E/N0) with the N0 the filter sees, in all cases. (2) Noise-like pulse with the square law: square → average (pipeline) sits at the radiometer bound a√(B∫(g−⟨g⟩)²dt) for every f_out; square → keep one, or average the voltages → square, grow as √f_out and reach it only at f_out = B. The bound is set by B·T, not by the post-detection rate. Full discussion: logs/2026-10-09_fout-study.md.

demoBinningMatchedFilter (demo, 9 Oct)

A script for explaining the binning, run section by section. Noise-like pulse (complex, 100 MHz, P 10 ms, FWHM 0.5 ms, peak 3.4 % of the noise), detected power, matched filter (1) at 100 MHz, (2) after averaging into 10 kHz bins, (3) after keeping one sample per 10 kHz bin. Measured SNR (100 trials) 21.5 / 21.4 / 0.23 vs predicted 20.0 / 19.9 / 0.20: binning loses only the 0.5 % smearing of a 100 µs bin and is ~130× faster (0.58 ms incl. binning vs 78 ms via FFT, timeit; a direct convolution at full rate ~10¹⁴ operations); decimation without averaging loses √10000 = 100× in SNR. Timing, operation counts and memory are printed and shown under each matched-filter panel.
