## 1. In one paragraph

The synthetic chain (pulsar → dispersion → receiver noise + RFI → IQ) and the processing chain
(filterbank → RFI excision → per-channel coherent dedispersion → detection → fold → TOA +
detection) exist and are validated against ground truth. The error bars are honest and the
detector's false-alarm rate is as designed. All of this was shown on 0.1 s of data from a
bright pulsar (−5 dB), with sweeps down to −25 dB. The design point is −54 dB, with about 20 h
per TOA folded across several passes. Closing that gap is the work of blocks C (fast simulator)
and D (phase prediction). Git: `main` = `origin/main` = `849ccf5`; no commits since 9 Oct.

## 3. Default processing path (`main.m`)

channelizeIQ (128 × 3.125 MHz) → detectRFI (windows 1–16 samples, PFA 1e-6, guard 10,
FreqGuard 7) → blankChannels → dedisperseChannels → detectChannels (0.96 µs bins) →
blankingWeights → foldProfile ('DataWeights', 2048 bins, 1 turn/sub-int) → estimateTOA /
detectPulsar ('optimal'); good TOA = valid & detected (unknown phase) & χ² ok. The full-band
path stays as the reference. Code: 28 functions, 7 scripts, 19 tests/experiments (~13.6k lines);
docs site 26 pages; `data/` 28 GB (14 GB in `data/mc`).

## 5. Design target (reference scenario, notes §11)

3×3 array, dual pol, 1.2–1.6 GHz, ground station, site-independent. Worst-case design point
SEFD ≈ 7.4e5 Jy → J0437 at ρ ≈ −54 dB, ~20 h per TOA (σ ≈ 12 µs ≈ 3.6 km). J0437 is the only
realistic MSP (southern only); Vela is as good per √time, but has DM 67.8 and glitches.
B0329+54 is the northern option. A 3-D fix needs ≥ 4 pulsars, so bright normal pulsars are
needed too.

## 7. Review observations (Claude)

1. Biggest risk = the gap between what is validated (−5 dB, 0.1 s, one pass) and the design
   point (−54 dB, ~20 h, folded across passes with Earth motion). C and D are the critical path.
   B was closed for that reason.
2. Regression protection: the units added since 6 Oct have unit tests, but the original stages
   (generator, dispersion, IQ, full-band dedispersion, detectPower) were validated by runs and
   NumPy ports only, and there is no single "run all tests" entry point. C will reuse the fold
   struct contract; a frozen reference fold/TOA set already exists (`makeFoldReference`,
   `makeToaReference`).
3. The same stage calls are repeated across main and the run scripts (§10 item 7). This is
   cheaper to fix before C adds another consumer.
4. Generator-side DM ≤ 100 (forward dispersion ~94 GB) blocks voltage-level Vela runs, but
   not J0437 (DM 2.6) and not C (profile level).
5. For real hardware: receiver dynamic range / ADC clipping is not modelled. A +40 dB radar
   would clip a few-bit ADC. This may matter as much as excision.
