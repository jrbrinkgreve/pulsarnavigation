## B design note (agreed: "keep B first, go ahead with B1")

Physics:
1. **Where to cut:** before dedispersion (radar = 2 µs blip in 1–2 channels; after
   per-channel dedispersion ~60 µs, full band 6 ms) → between `channelizeIQ` and
   `dedisperseChannels`.
2. **Channel noise is nearly white:** from the channelizer prototype (3853 taps,
   decimation 192) the lag-1 autocorrelation is 0.05 (11 lags above 1e-3). Power averaged
   over n samples ≈ Gamma with n_eff ≈ n (n = 16 → 15.8). Thresholds (× mean power) for a
   false-flag chance of 1e-6 per window: 13.8 (1 sample, 0.24 µs), 5.4 (4), 2.7 (16),
   1.7 (64), 1.33 (256 = 61 µs).
3. **What must be cut:** only RFI whose power follows the pulsar's phase biases a TOA.
   Pulsed / impulsive RFI must be blanked (scenario radar ~+38 dB per channel while on).
   Constant-envelope RFI (carrier, GNSS) is phase-uniform, and the 'optimal' fit already
   weights each channel by 1/level² (variance from the fitted level a_c), so a strong
   carrier channel gets almost no weight. Noise-like RFI (LTE/OFDM) cannot be detected;
   it is extra noise, handled by the weighting.
4. **Data-dependent flags:** the A3a weights are exact for a data-independent mask; a
   detector removes the highest samples (tiny, phase-uniform at weak SNR). At −5 dB the
   pulsar raises the on-pulse power by 32 % and triggers long windows: on-pulse flag rate
   3e-5 (1 sample), 5e-4 (16), 1e-2 (64), 0.43 (256) vs 1e-6 off-pulse. From −20 dB down,
   ≤ 2.3e-6 at every window. → windows 1–16 samples by default.
5. **Guard:** a channel sample mixes ~20 input samples (3853/192) → ±10 samples (±2.4 µs).

Plan (one function per step): **B1** `blankChannels` → **B2** `detectRFI` (multi-scale
power threshold, robust median baseline per ~16 ms block, exact thresholds, guard) →
**B3** hook in `main.m` / `pipelineParams` → **B4** characterize the 5-source scenario
(channel path with / without excision vs the 5 Oct full-band table) → **B5** realistic
L-band scenario (rotating ATC radar, 400 Hz locked radar, GNSS L1/L2/E6, Inmarsat, LTE;
frequencies to verify) → **B6** spectral kurtosis / whole-channel flags only if needed.

Noticed: the scenario radar (1300 MHz) and carrier (1350 MHz) sit exactly on channel
boundaries (32/33, 48/49); the dedispersion edge taper is zero there, so the carrier
would look harmless on the channel path for the wrong reason → move it off the grid in
B4 (e.g. 1351.3 MHz). A radar locked to the pulsar period is the hard case at −54 dB
(residual after blanking may exceed the pulsar if it folds in place each turn); in
reality Doppler decorrelates topocentric RFI over long folds (block D).

Decisions: blanked **copies** of the channel files (raw kept); power threshold only in v1;
windows 1–16 samples; P_FA 1e-6 per window; guard ±10 (all confirmed by Jasper).

Question asked: state of the fast simulator (C)? Not started; design draft of 6 Oct in
notes §10 item 3 (written before block A: needs the per-channel fold, multi-lag noise).
Its noise-only part no longer depends on B; Jasper: keep B first.

## B1 `functions/blankChannels.m` (new)

`info = blankChannels(info_chan, mask, outBase)`: mask rows [channel, first, last]
(format of `blankingWeights`; clipped, overlaps / unsorted allowed, empty rows ignored)
→ blanked copies `<outBase>_ch###.dat` (masked samples = 0, everything else copied
bit-exactly), streamed in blocks (`BlockSize`, default 2^20). The returned info is
`info_chan` with the new `file` / `chanFiles` plus `rawFile`, `mask` (normalized:
sorted, merged, clipped), `nMaskRows`, `blankedSamples`, `blankedFraction`, so
`dedisperseChannels` and `blankingWeights` take it unchanged. Refuses to overwrite the
raw files.

`tests/testBlankChannels.m` — ALL PASSED in Claude's run and **Jasper's run → B1 validated**:
1. 1727 mask rows, 5.175 % of samples: masked samples exactly 0, others bit-identical,
   counts per channel right.
2. Explicit merge / clip cases (channels 2, 5, 7, 128) right; normalized mask fed back →
   identical files, same mask.
3. BlockSize 4099 = one block (identical files).
4. Empty mask → byte-identical copies; info = info_chan apart from file names.
5. `loadInfo` works; `dedisperseChannels` on the blanked info: same grid, the 83
   unblanked channels bit-identical to `data/chan/test_dedisp_chan_*`; channel 128
   (blanks at both file ends): change beyond the filter reach (−1467 / +1334 samples)
   7.9e-7 of the rms (rounding), within the reach 0.73.

Not changed: the inline helper `blankChannelFiles` in `tests/testBlankingWeights.m`
(validated test; could call `blankChannels` instead — ask).

## B2 `functions/detectRFI.m` (new)

`[mask, info] = detectRFI(info_chan)`: per channel, power |x|² of the raw channel samples;
baseline m per 16 ms block = median / ln 2 (exponential power; fully supported samples);
windows of 1, 2, 4, 8, 16 samples (stride max(1, n/2)) flagged when mean > η_n·m; every
flagged window widened by the guard (prototype half-length = 10 samples) and merged into
mask rows [channel, first, last]; pass 2 re-estimates m without the flagged samples.
Options `Scales`, `PFA`, `Guard`, `BaselineTime`, `Passes`, `KeepWindows`. Uses only the
channel data and the channelizer settings.

**Change vs the design note: exact thresholds.** The first version used the Gamma
distribution with the matched variance (n_eff). Test 1b showed too many false flags for
n = 4–16 (+1–3 % at PFA 1e-3, +8–9 % at 1e-4, +20–58 % ± 20–66 % at 1e-6). Cause: the window
power is exactly Σ λ_k E_k (E_k unit exponentials, λ_k eigenvalues of the n × n
correlation matrix, 0.61–1.05 for n = 16); its tail is heavier than the Gamma's (exact /
Gamma 1.02 / 1.04 / 1.08–1.10 at 1e-3 / 1e-4 / 1e-6). Now η_n solves the exact survival
function, computed as a chain of exponential stages (phase-type): [1 0 … 0]·expm(Q x)·1.
Thresholds at 1e-6: 13.82, 8.39, 5.39, 3.68, 2.69 (Gamma: 13.82, 8.36, 5.36, 3.67, 2.68).

`tests/testDetectRFI.m` (~33 s; makes its own 0.05 s noise-only and noise + RFI channel
files through addNoiseAndRFI → applyIQmodulation → channelizeIQ with the same noise seed,
so their difference is the RFI alone) — ALL PASSED in Claude's run (Jasper's run pending):
1. Noise only: (a) baseline / block mean 1.00008 ± 0.00020; (b) false windows / expected
   per scale at 1e-3: 0.989–1.004 (± 0.006–0.017), at 1e-4: 0.989–1.056 (± 0.02–0.06);
   (c) defaults: flagged windows as expected, clean data blanked 5.4e-5 (bound 6.7e-5).
2. −5 dB pulsar (seed-43 files; channels 4–125, outside the dispersion stage's 8 MHz
   band-edge taper, where the simulated pulse is weaker — including them gave a 4 %
   on-pulse deficit): flagged windows on / off the pulse match the prediction per scale
   (e.g. 256 samples: 3441 vs 3441). Blanked fraction on-pulse 9.3e-4 vs off-pulse 4.5e-5
   with the default windows; **13.9 % of the on-pulse samples** with windows up to 256
   → confirms the 1–16 default.
3. RFI: radar — all 19 pulses blanked in channels 32–33, energy removed in channels 31–34
   1 − 8e-8; impulses (1000/s) — 98.65 % of their energy removed (expected ~98 %: per
   channel a burst's energy is ~exponential, the weakest stay below threshold); carrier
   and GNSS channels — no flags of their own (baseline 47× / 7× / 14× the noise; impulses
   are not caught there either, which is acceptable: the 'optimal' fit gives those
   channels little weight).

**Finding: radar sidelobes.** The simulated radar pulse switches on/off instantly, so its
spectrum has sinc sidelobes (~1/f²): 1.3 % of its energy lies outside channels 32–33 and
the detector flags channels 27–39 at the radar pulses. Over all channels 0.18 % of the
radar energy stays (far channels, below threshold per channel). Unlocked (373 Hz): phase-
uniform, harmless. Locked at −54 dB: 0.18 % × ~80,000 ≈ 140 pulsar pulses' worth per radar
pulse could fold in place → Doppler (D) or a periodic mask needed. Real radars have finite
rise times (less splatter) → rise-time option for `rfiSource` in B5.
